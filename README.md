# 样本交接链路审计（Sample Chain-of-Custody Audit）

基于 **Python FastAPI + SQLite + 原生 HTML/CSS/JavaScript** 的样本交接链路审计网页。
为每个样本录入带有**时间区间**与**经手人**的交接事件后，系统按起始时间排序，
自动校验保管链路是否存在：

- 🔴 **保管断档（gap）**：上一任归还后、下一任接手前，存在无人负责的时间段；
- 🔴 **交接重叠（overlap）**：两个（含不相邻的）经手人在同一时间段同时持有样本，
  或上一任尚未归还下一任即接手；
- 🟠 **逆序录入（out-of-order）**：录入顺序（seq）与交接时间顺序不一致（事后补录）；
- 🔴 **起止倒置（reversed interval）**：单条事件结束时间早于起始时间。

时间线上以泳道条带展示各段保管区间，并叠加高亮断档（紫色斜纹）与重叠（红色）区域；
同时给出统计数字与**可读的中文审计结论**。支持编辑/删除事件，以及导出当前样本的
**Markdown / HTML / JSON** 审计报告。

审计完成后，审计员可对当前结论执行**结论签署**：填写签署人、签署时间与备注后，
系统保存一份包含样本信息、交接事件与审计发现的**不可变快照**（附 SHA-256 校验值）。
此后事件的任何增删改都不会改写历史快照；快照支持列表查看、详情核对与**撤销签署**
（撤销必须填写原因，原快照保留，仅标记状态）。导出的审计报告会自动附上签署记录。

系统还为每对按审计排序相邻的事件生成**双向交接确认**：交出方与接收方分别填写
确认人姓名和确认时间；只有**两侧均确认且上一段结束时间严格等于下一段开始时间**，
交接项才标记为「已确认」，否则显示「待确认」或「时间不一致」。每次确认都绑定
两条事件当时的关键字段摘要（经手人 / 起止时间 / 备注）并生成 SHA-256 摘要；任一
事件后续被编辑、删除，或新增事件导致两条记录不再相邻时，原确认保留为**失效记录**
（不再计入有效状态），必须由两侧重新确认。导出报告会逐项列出交接状态。

除单条录入外，「交接事件」卡片还提供 **批量导入**：上传 **UTF-8 编码的 CSV**
（表头固定为 `经手人,开始时间,结束时间,备注`），系统先解析为**预览**——逐行标注
校验错误、模拟全部行导入后的审计结论变化（预览不写库），并返回绑定当前事件链的
**摘要令牌**；确认导入时须携带该令牌，服务端在单一事务内重新解析校验并核对链路，
预览后事件链发生过任何增删改都会被拒绝并要求重新预览；仅当全部行有效时才按文件
顺序一次性分配 `seq` 写入并刷新交接确认失效状态，任一失败整体回滚。

## 快速开始（Docker Compose，推荐）

```bash
docker compose up -d --build
```

启动后访问固定端口：

> http://localhost:8080

容器启动时会自动完成：

1. 安装 Python 依赖（镜像构建阶段）；
2. 初始化 SQLite（建表，写入 2 个演示样本，数据文件位于 `/data/audit.db`，
   通过命名卷 `audit-data` 持久化）；
3. 启动 uvicorn 监听 `8080`。

停止 / 清理：

```bash
docker compose down          # 停止并删除容器（保留数据卷）
docker compose down -v       # 同时删除数据库卷
```

## 本地开发运行（不用 Docker）

需要 Python 3.11+：

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

uvicorn app.main:app --host 0.0.0.0 --port 8080 --reload
```

数据库默认创建在 `app/audit.db`（首次启动自动建表并写入演示数据）。
可通过环境变量 `AUDIT_DB_PATH` 自定义路径。

运行测试：

```bash
pytest -q
```

## 使用说明

1. 点击右上角 **＋ 新建样本**（编号唯一），或从左侧选择演示样本；
2. 在「交接事件」卡片填写经手人、起始时间、结束时间（**留空表示当前仍在保管中**）、备注，
   点击 **登记交接事件**；
3. 审计结论、统计与时间线实时刷新。时间条按起始时间排列，冲突事件标红，
   点击下方「审计发现」条目可高亮对应的时间条与表格行；
4. 点击事件行的 **编辑** 可修改任意字段（录入序 seq 保持不变，便于追溯补录行为），
   保存后重新审计；也可删除事件；
5. 在「结论签署」卡片填写签署人、签署时间（默认当前时间）与备注，点击
   **签署当前审计结论** 生成不可变快照；列表中点击 **详情 / 撤销** 可查看快照完整内容
   （含完整性校验），有效签署可在详情弹窗中填写原因后撤销，撤销后原快照保留；
6. 在「双向交接确认」卡片可看到按审计排序生成的全部交接项：点击 **填写确认**，
   在弹窗中选择交出方 / 接收方并填写姓名与确认时间（默认当前时间）；两侧均确认后
   系统按交接时点判定「已确认」或「时间不一致」。事件被编辑、删除或相邻关系变化后，
   原确认会移入下方「失效的历史确认」列表，可查看绑定摘要，交接项需重新确认；
7. 通过「交接事件」卡片右上角的 **导出审计报告** 下载 Markdown / HTML / JSON 三种格式之一，
   报告末尾自动附上全部签署记录（含状态与撤销原因）以及各交接项的确认状态；
8. **批量导入**（同一卡片右上角 **⤒ 批量导入 CSV**）：
   - 先点击 **⬇ 下载 CSV 模板** 获取格式模板（UTF-8 带 BOM，Excel 打开不乱码）；
   - 按模板填写后选择文件即自动进入**导入预览**：逐行显示校验结果（含错误原因、
     将分配的录入序 seq），并对比「导入前 / 确认导入后」的审计结论与统计；
     预览**不会写入数据库**；
   - 只有全部行有效时 **确认导入全部行** 按钮才可用。确认时浏览器会重新上传
     同一文件并携带预览令牌；服务端在**单一事务**内重新解析校验、核对事件链摘要，
     预览后该样本的事件链若发生过增 / 删 / 改（含其他人的并发操作），整单拒绝并
     提示「请重新预览」；
   - 导入成功后弹窗给出结果汇总：导入行数、seq 区间、新增事件 id、因相邻关系
     变化而失效的既有交接确认条数、以及导入后的审计结论；随后页面自动刷新。

演示样本 `SAM-DEMO-001` 预置了断档、重叠与逆序补录，`SAM-DEMO-002` 是无缝链路，
开箱即可对比两种审计结果。

## 批量导入 CSV 格式

- 编码：**UTF-8**（模板为 UTF-8 with BOM；无 BOM 也可接受，其他编码会被拒绝）；
- 首行为固定表头，顺序与名称必须为：

  | 列 | 必填 | 格式 | 说明 |
  | --- | --- | --- | --- |
  | 经手人 | 是 | 文本，≤64 字符 | 与单条录入相同，不可为空 |
  | 开始时间 | 是 | `YYYY-MM-DD HH:MM:SS` | 日期与时间之间用空格或 `T` 分隔；可只写到分钟（自动补 `:00`） |
  | 结束时间 | 否 | 同上 | **留空表示当前仍在保管中**；不得早于开始时间 |
  | 备注 | 否 | 文本，≤512 字符 | 含逗号 / 换行时按 CSV 规则用双引号包裹 |

- 单次最多 1000 个数据行、文件上限 2MB；空行自动跳过；
- 录入序 `seq` 在确认导入时按**文件行顺序**连续分配（接在当前最大 seq 之后），
  导入不改变既有事件的 seq；
- 校验与单条录入完全一致：经手人缺失、时间无法解析、起止倒置等会逐行列错；
  **任一行无效则不能导入**（不会写入任何行）；
- 两阶段并发控制：预览返回的令牌（HMAC 签名，30 分钟有效）绑定样本 id、
  文件 SHA-256 与预览时事件链摘要；确认时在单一事务（`BEGIN IMMEDIATE`）内
  再次校验，链路已变更 / 文件被改动 / 令牌过期或伪造都会被拒绝，需重新预览；
  成功提交后令牌即失效（再次提交会因链路摘要变化被拒绝），杜绝重复导入。

模板示例（页面可直接下载）：

```csv
经手人,开始时间,结束时间,备注
张三（采集组）,2026-09-18 09:00:00,2026-09-18 10:00:00,现场采集并密封
李四（运输组）,2026-09-18 10:00:00,2026-09-18 11:30:00,冷链运输 2-8℃
王五（检测组）,2026-09-18 11:30:00,,结束时间留空表示当前仍在保管中
```

## 审计规则说明

| 规则 | 判定方式 | 级别 |
| --- | --- | --- |
| 断档 gap | 按起始时间排序后，相邻两段 `cur.start > prev.end`，差值即断档时长 | 冲突（审计不通过） |
| 重叠 overlap | 相邻段 `cur.start < prev.end`；开放保管（无结束时间）之后又出现新段；以及任意两段非相邻区间的时间交叉 | 冲突 |
| 起止倒置 | 单条事件 `end < start` | 冲突（该条不参与区间链计算） |
| 逆序录入 | 时间更早的事件录入序 `seq` 反而更大 | 告警（链路本身可通过） |

结论分三档：`pass`（无缝衔接）、`warning`（链路连续但存在逆序补录）、
`fail`（存在断档/重叠/倒置）。

## 双向交接确认

- 交接项由系统按审计排序（起始时间升序；起止倒置事件不参与）的**相邻事件对**
  自动生成，上一段为交出方、下一段为接收方，无需手工配对；
- 状态机：

  | 状态 | 判定 |
  | --- | --- |
  | 已确认 confirmed | 交出方、接收方均已填写姓名与确认时间，且交出结束时间 = 接收开始时间 |
  | 待确认 pending | 尚未两侧齐全（含只有一侧确认），或时间一致但等待另一侧 |
  | 时间不一致 time_mismatch | 两侧均已确认，但交出结束时间 ≠ 接收开始时间（含交出方仍在保管） |

- 每条确认在**首次发起时**绑定两条事件当时的关键字段摘要（经手人、起始时间、
  结束时间、备注）并记录 SHA-256 摘要；
- 事件被编辑（任一字段变化）→ 原确认以 `event_edited` 失效；事件被删除 →
  `event_deleted`；新增 / 调整事件导致两事件不再相邻 → `adjacency_changed`。
  失效只更新状态 / 原因 / 失效时间，原行与快照永久保留，不再计入交接项有效状态，
  必须两侧重新确认（重新确认生成新记录）。

| GET | `/api/samples` | 样本列表（含事件数） |
| POST | `/api/samples` | 新建样本 |
| GET | `/api/samples/{id}` | 样本详情 + 事件 + 审计结果 + 签署快照摘要 |
| DELETE | `/api/samples/{id}` | 删除样本（级联删除事件与签署快照） |

| DELETE | `/api/events/{id}` | 删除交接事件 |
| GET | `/api/import-template` | 下载 CSV 导入模板（UTF-8 带 BOM） |
| POST | `/api/samples/{id}/events/import/preview` | 上传 CSV 生成导入预览（逐行校验 + 审计变化，不写库，返回摘要令牌） |
| POST | `/api/samples/{id}/events/import/confirm` | 携带令牌与同一 CSV 确认导入（multipart 表单：`file` + `token`，单一事务） |
| GET | `/api/samples/{id}/audit` | 仅获取审计结果 |
| POST | `/api/samples/{id}/signoffs` | 结论签署：保存当前审计结果的不可变快照 |
| GET | `/api/samples/{id}/signoffs` | 签署快照列表（状态 + 审计摘要） |
| GET | `/api/signoffs/{id}` | 快照详情（完整快照 + 完整性校验） |
| POST | `/api/signoffs/{id}/revoke` | 撤销签署（需原因，原快照保留） |
| GET | `/api/samples/{id}/handovers` | 双向交接确认：交接项状态 + 失效历史记录 + 统计 |
| POST | `/api/samples/{id}/handovers/confirm?from_event_id=&to_event_id=` | 交出方（side=`from`）或接收方（side=`to`）确认，需姓名与确认时间 |
| GET | `/api/handovers/{id}` | 交接确认记录详情（双方信息、绑定事件摘要、失效原因） |
| GET | `/api/samples/{id}/report?format=markdown\|html\|json` | 导出审计报告（带下载文件名，含签署记录与各交接项状态） |

交互式 API 文档：http://localhost:8080/docs

## 技术说明

- 时间存储为 SQLite 文本 `YYYY-MM-DD HH:MM:SS`，应用层统一解析为 naive datetime 比较；
- `events.seq` 为不可变的录入顺序（自增），审计排序按 `start_time`，二者不一致即为逆序录入；
- 签署快照以 JSON 文本整体存入 `signoffs.snapshot`，并记录 SHA-256 校验值；
  撤销仅更新 `status / revoke_reason / revoked_at`，快照内容从创建起无任何接口可修改；
- 双向交接确认存于 `handovers` 表：两侧确认列、两条事件确认当时的关键字段 JSON 摘要
  与合并 SHA-256；事件编辑 / 删除 / 相邻关系变化只把原行置为 `invalidated`
  （记录原因与失效时间），原行不删除、不计入有效状态；`handovers` 的事件列不加
  级联外键，事件删除后失效记录仍可查，删除样本时随样本一并级联清除；
- 无外部前端构建步骤，静态资源由 FastAPI 的 `StaticFiles` 直接提供；
- 批量导入的预览令牌为无状态令牌（HMAC-SHA256，进程内随机密钥，30 分钟有效），
  令牌体绑定样本 id、文件 SHA-256、有效行数与预览时事件链摘要（事件数 + 各事件
  关键字段有序哈希）；确认接口在 `BEGIN IMMEDIATE` 单事务内复核后才顺序写入，
  因此预览不落库、确认全有或全无，且能检测预览后的任何链路增删改；
- 文件上传依赖 `python-multipart`；
- 服务进程在容器内以非 root 友好的方式运行于固定端口 **8080**，数据与镜像分离。
